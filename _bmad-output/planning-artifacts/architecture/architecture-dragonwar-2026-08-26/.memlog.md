- (decision) AD-1 Paradigm: ports-and-adapters around a VIRTUAL PINBALL MACHINE - Rules is the game CPU (domain core), Physics is the cabinet behind a virtual I/O board (switches in, coils out), Presentation = drivers (lamps, flashers, GI, display, audio, camera), Host = composition root. Dependency direction: host -> presentation -> sim/contracts+table; host -> sim/loop -> physics+rules; physics and rules never import each other; sim/** never imports presentation, host, Babylon or DOM globals.
- (decision) AD-2 Two event streams out of physics: SwitchEvent {switch, closed, tick} -> rules only; ContactEvent {kind, speed, surface, pos, tick} -> presentation only. Rules never receive contact events and never read ball position/velocity. Prevents velocity leaking into rules and keeps rules headless.
- (decision) AD-3 Single simulation clock: tick (uint32, 1 kHz) is the only time inside sim; every rules timer (ball save, grace, hurry-up, ball search, tilt debounce/settle, mode timers) counts ticks; wall-clock enters only in the host accumulator. All rules randomness (Match, skill-shot lane) via a seeded PRNG stored in state; seed recorded in the replay header. Prevents non-deterministic timers and unreplayable games.
- (decision) AD-4 Loop contract: host accumulator owes N steps per frame; rules.step runs after EVERY physics step with that step's switch events (possibly empty); commands issued at tick t apply at t+1; inputs sampled once per step from a host-latched InputFrame; catch-up capped at 200 ms of simulated time, beyond which owed time is discarded (VPX bailout). Replay = seed + table/tuning hash + per-tick input diffs. Presentation renders the latest snapshot, no interpolation.
- (decision) AD-5 Flippers and plunger are HARDWARE RULES inside physics: button -> solenoid model runs in the physics step, gated by rules command flippers.enable(bool). Button presses also surface to rules as cabinet switches (s_left_flipper, s_right_flipper, s_start, s_plunger) for lane change, mode select, initials. Nudge -> cabinet oscillator in physics; bob closure -> s_tilt_bob switch. Prevents flipper latency through rules and two owners of flipper state.
- (decision) AD-6 Ball ownership: physics owns ball BODIES; rules owns ball ACCOUNTING (MPF ball controller: balls in play, per-device counts, per-player lock credits). Every ball_device (trough, plunger lane, Lock) parks an entering ball (removed from the simulated set) and reports entry via its switch; physics ejects only on CoilCommand eject(device) and spawns the ball at the device's eject pose. Rules decide lock vs mode-start vs strike from state; physics only reports entry. Prevents two owners of where-is-ball-2.
- (decision) AD-7 GameState shape: one plain-data JSON-serializable tree {tick, phase, machine, players[], currentPlayer, modes[], rng}. Player-scoped facts (score, letters, lock credits, modes played, tilt warnings, bonus, extra balls) live ONLY under players[i]; machine-scoped facts (device ball counts, balls in play, flippers enabled, ball-save timer, tilt state, jackpot seed) ONLY under machine; mode-local timers/counters under modes[i]. Mutated only inside rules.step; no class instances or closures. Prevents credits stored on the device / device counts on the player.
