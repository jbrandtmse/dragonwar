## Intent

**Problem:** Nothing in `GameState` ever moves. `phase` is written once as the literal `'attract'` (`src/sim/loop/index.ts:230`) and never transitions; `PlayerState` is a fully-declared type with **zero constructions anywhere in `src/`**; `players` is always `[]`, `rng` always `0`, `modes` always `[]`, and `hardwareEnabled` is an inert field with **zero readers**. A ball reaches the playfield only through the dev-only `pulseCoil('c_trough_eject')` escape hatch (`src/sim/loop/index.ts:374-376`, whose own header names this story as its replacement) or a golden's declared coil prologue. Separately, `GameState.machine.deviceSlots` is written by `sim/loop` **after** `rules.step()` returns (`src/sim/loop/index.ts:351-355`), a live AD-7 violation (`DW-70`) that `pnpm check:ad7` has named in red for the whole epic.

**Approach:** Introduce the ball controller as the owner of the real ball lifecycle — Start creates a game and a player from `GameStart`, further Start presses add players up to four before ball 1 ends, the controller alone pulses `c_trough_eject` to serve, a drain ends the ball and rotates to the next player or the next ball, and the last player's last ball ends the game — and, in the same change, make `machine.deviceSlots` derived **inside** `rules.step()` so AD-7 finally holds, flipping `pnpm check:ad7` from its deliberate red to green while rewriting the in-suite wrapper into a gate whose red is still demonstrable.

## Boundaries & Constraints

**Always:**

- **AD-7 is the governing decision and this story is where it becomes true.** `GameState` is JSON-serializable, no class instances or closures, **mutated only inside `rules.step`**. After this story no file outside `src/sim/rules/**` writes any field of `GameState`.
- **AD-19: the ball controller consumes device events, never a raw switch.** `s_start` arrives as `button_pressed { button: 's_start' }`; a drain arrives as `device_ball_entered { device: 'bd_trough', slot }`; a plunge arrives as `ball_launched`. `s_drain` is deliberately unmapped (`test/rules-devices.test.ts:504-516`) and must stay so — `tools/boundary-lint.mjs`'s `rules-no-switch-event-outside-devices` check fails the build on even *naming* `SwitchEvent` outside `src/sim/rules/devices/`.
- **AD-18: only the ball controller pulses `c_trough_eject` / `c_autolaunch` and mutates `ballsInPlay`.**
- **AD-4: commands issued at tick *N* are consumed by physics at *N+1*.** `RulesStepResult.coilCommands` -> `pendingCommands` (`src/sim/loop/index.ts:365-367`) is the channel Story 2.4 built; `step()`'s three-argument signature is AD-4's pin and **must not change**.
- **Rule 19 governs every AC.** A negative assertion carries a positive control **in the same test**; a threshold is straddled on both sides; every AC records a demonstrated `mutation:`.
- Re-measure every baseline at your own tree (see `## Verification`); never carry a figure forward.
