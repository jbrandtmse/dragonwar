## Intent

**Problem:** The table has no lights. `TABLE.lamps` holds one Story 1.4 placeholder (`l_insert_left`) that nothing drives, `src/sim/rules/lamps.ts` does not exist, and `src/presentation/lighting/` holds only a `.gitkeep` — so the lit lanes, the DRAGON letters and the Lock that Stories 2.5 and 2.7 already track in `GameState` are invisible, and a player cannot read the table without instructions (PRD FR-43, FR-44).

**Approach:** Author the fourteen insert lamps the game already has state for — three Top lanes, four inlane/outlane, six DRAGON letters, the Lock — as `TABLE.lamps` entries and as `l_` lens-and-cup meshes in the Blender source; add `lampsOf(state): LampState` as a pure projection in `src/sim/rules/lamps.ts`; make `sim/loop` emit only the per-step diff as `LampCommand`s; and add `presentation/lighting/grammar.ts` (the one `(role, step)` → RGB/intensity/cadence table) plus the `LampDriver` that drives each insert's emissive material and a dynamic light beneath its lens. Rules speak roles and steps; only presentation knows a colour.

## Boundaries & Constraints

**Always:**
- **AD-9 is the contract.** Lamp state is a *pure projection* `lampsOf(state)` recomputed every rules step from `GameState` alone; `sim/loop` emits the **diff** as `LampCommand`s; `step ∈ {0 off, 1 lit, 2 emphasised, 3 urgent}` is the only progression rules may express; `role ∈ { off, lit, hurryup, quickmb, joust, dragon, special }` — **never a colour**; `presentation/lighting/grammar.ts` is the one `(role, step)` → RGB/intensity/cadence table, with blinking timed by presentation. The `.blend` is edited **only** through `tools/make-placeholder-blend.py`, never in the UI.
- **AD-10 frames.** Geometry is authored unpitched in the **table frame** (playfield-local millimetres, right-handed: +X right, +Y up-table away from the player, **+Z normal to the playfield toward the glass**). **The four measured traps this story is walking into, and the assertion that closes each.** Every one was reproduced under `NullEngine` against the committed glb during planning, and every one is silent — none produces a failing test on its own.
1. **One shared material.** The glb carries four materials, one per mesh, but `make-placeholder-blend.py:3274` appends the single `mat_insert` datablock. Fourteen inserts reusing it means Babylon's glTF loader hands all fourteen meshes the **same `PBRMaterial` instance**, so lighting lamp A lights lamp B identically. A single-lamp test cannot see it. → `material.clone()` per insert, pinned by the "lamp A lit, lamp B still black" control (task 24).
2. **`getAbsolutePosition()` lies under `NullEngine`.** `ShadowLight.getAbsolutePosition()` returns `transformedPosition ?? position`, and `transformedPosition` is only populated by `computeTransformedInformation()`, which the engine calls from the shader-bind path — never under `NullEngine`. Measured: a light parented to a 6.5°-pitched `playfield_root` read `y = −0.004` from `getAbsolutePosition()` against a true world `y = 0.05263` — **57 mm wrong, and plausible-looking**. → assert via `computeWorldMatrix(true).getTranslation()` against the mesh's `boundingBox.centerWorld`.
3. **`maxSimultaneousLights = 4`.** `mat_insert` arrives from the loader with Babylon's PBR default of 4, and `BindLights` silently truncates `Math.min(mesh.lightSources.length, 4)`. Twenty authored lights would render four. Because `NullEngine` compiles no shaders, this is unobservable through the render path. → `includedOnlyMeshes = [own mesh]` (so each insert sees hemispheric + 1) plus the per-mesh `lightSources ≤ maxSimultaneousLights` assertion. This is also why the insert lights deliberately do **not** include `vis_playfield`: FR-43's spill onto adjacent playfield art is AD-12's per-group bake in Epic 4, and adding `vis_playfield` to every insert light would blow the four-light material limit at the fifth lamp.
4. **`scene.lights` counts disabled lights.** `setEnabled(false)` removes a light from `mesh.lightSources` but not from `scene.lights`. A budget assertion written against `scene.lights.length` counts lights that cost nothing and reports a pool size rather than a live count. → count `scene.lights.filter((l) => l.isEnabled())`, and exercise the cap with an injected `{ budget: 2 }` over fourteen lamps, because 14 < 20 makes the real-budget assertion vacuous on its own.
