## Design Notes

### Why this is one story and not twelve

Chartered by the Epic 1 burn-down gate (Rule 17) from thirty-five `owner:burndown` entries against a cap of 8, selected by severity, then occurrence count, then lowest fix-risk: five MEDs (`DW-32`, `DW-39`, `DW-74`, `DW-75`, `DW-84`) and seven low-fix-risk LOWs. Frontmatter carries `multiple-goals` honestly -- the twelve are independent by construction -- but they ship together because a burn-down's value is closing the epic with the ledger drained, not in any one item. `DW-33` is the notable exclusion (LOW severity, MED fix-risk, went to Story 2.1). The thirteen `escalated` / `decision-pending` entries -- `DW-70`'s live AD-7 violation and `DW-2`'s `TICK_HZ` ratification among them -- were set aside untouched for the user's decision sheet, because a burn-down story cannot ratify a tick rate or run a playtest.

### Three of the twelve are vacuity bugs, so the anti-vacuity discipline is the story

`DW-39` is literally "the fixtures never prove the exemptions hold". `DW-71` is "the assertion can fail for a reason unrelated to its name". `DW-84` is "the path is constructed and guarded but never run". Fixing those with more unfalsifiable assertions would leave the epic exactly where it started -- and this epic has already shipped **four** structural vacuities (Story 1.6's `pass_commands_empty` against a `readonly never[]`; Story 1.8's "real contact" assertion true with no flipper input; Story 1.9's `plungerSpeedByHoldMs` assertion that could not fail, and its Export byte-identity assertion that compared a file to itself). Three specific traps found while planning, each with its counter already written into the tasks:

1. **`DW-39`'s own fixture would be vacuous by default.** The `sim-no-literal-ms` exemption at `tools/boundary-lint.mjs:409` is not load-bearing today: no binding in the real `tuning.ts` matches `MS_BINDING_PATTERN`, because `entry(` sits between the `:` and the numeral. A positive fixture that copies the real file's style would prove nothing. It must contain a bare `const nudgeImpulseMs = 25;`.
2. **`DW-32`'s set difference is trivially green.** `src/` holds no orphan file today, so "every file is covered" passes against any implementation. The synthetic positive control -- feeding the comparison an uncovered path and asserting it is reported -- is what carries the discriminating power inside the suite; the tree mutation only demonstrates it once.
3. **`DW-75`'s clamp needs a no-op control.** Asserting "the transition lands inside the long frame" is satisfiable by a clamp that fires on every frame, which would be a worse defect than the one being fixed. The paired control -- an ordinary frame's stamp unchanged -- is what distinguishes the fix from a regression.

### `DW-75`: `epics.md` settles the contradictory matrix row; the fix stays host-side

Story 1.6's I/O matrix row (`spec-1-6-...:201`) is self-contradictory in its fourth column -- *"one after the last **clamps to it**, **and** `frameInForceAt` **carries it forward**"* -- and a clamped tick is by definition inside the frame and cannot be carried forward. `src/host/loop.ts:26-35` unilaterally resolved it in favour of "carries it forward" in a code comment that never went back into the spec. **`epics.md`'s Story 1.10 acceptance criterion settles it the other way** ("bounded to the last tick that frame actually runs, rather than landing past it and waiting in `pendingTransitions`"), so this is a decided question, not an intent gap. Story 1.6's spec is a done story's frozen intent block and is **not** amended; the code comment is what changes.

The fix belongs in `src/host/loop.ts`'s drain seam (`:147-149`), not in `sim/loop`'s `advance()`, for three reasons: (a) the wall-clock stamping is a host concern and AD-3 keeps wall-clock out of `sim/`; (b) clamping caller-supplied ticks inside `advance()` would be a semantic change to AD-4's loop contract, which the five goldens and the determinism tests pin; (c) it keeps this story out of `src/sim/loop/index.ts` entirely, and `DW-70`'s deliverable red lives at `:326-329` of that file.

The bound is provably a no-op inside the cap: `originMs` and `lastFrameMs` are both assigned from the same `nowMs` (`:137-138`, `:151`), and a DOM event's `timeStamp` is at or before the rAF callback's `nowMs`, so a stamp can never exceed the frame's own tick count except when the 200 ms cap discards owed time. The host cannot read `owedRemainderTicks` (`FrameOutput` is `{ snapshot, events, contactEvents, commands }` only), so the bound is conservative by at most one tick -- which is why the AC demands the no-op control rather than trusting the argument.

The ledger's second sub-defect -- "`tickAt` also ignores `advance()`'s `owedRemainderTicks`, so it can be one tick off on any frame whose elapsed time is not a whole number of ticks" -- is **not** in `epics.md`'s chartered AC and is **not** fixed here: closing it means widening a contract. If it survives implementation, it is recorded in frontmatter `deferred:` for the lead to harvest, with the residual restated.

### `DW-74`: the AC picks one of the ledger's two options

The ledger offered "either gate `applyCommands` on the map or drop the two unread keys". `epics.md`'s AC requires the first ("the pulse path consults the map and the coil does not fire"), so the choice is made. The same-tick ordering falls out of filtering at the `machine.ts:215` call site rather than inside the partition loop: every `enable`/`disable` in a tick writes the map before any pulse is filtered, so a disable wins regardless of array order. That is defensible and is pinned by an I/O matrix row rather than left incidental. AD-5 backs it: hardware rules are "gated only by `CoilCommand enable | disable` ... Tilt, game over and Attract disable all of them together" -- which is Story 2.11's consumer, and the reason a written-but-unread enable flag had to stop being dead state that looks live.

### Goldens: expected unchanged, required verified

Three of the twelve touch code the goldens run through, and all three are behaviour-neutral by construction: `DW-74`'s filter is a no-op with all four coils defaulting `true`; `DW-75`'s bound is a no-op inside the cap and no golden runs a >200 ms frame; `DW-81` escapes bytes in `source` strings that **do** reach `header.gameStart.tuning`, but `'\u00A7'` and the literal are the same runtime string and the hashes are computed over the parsed structure, never file bytes (`src/sim/loop/replay.ts:88-90`, `:108-115`, `:143-146`).
