# Epic 1 Context: First Flip — a ball and two flippers that feel right

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Epic 1 turns an empty repository into a playable vertical slice: the author opens a dev build in a browser and plunges, flips, cradles, taps, nudges and drains a single ball on a bare playfield built at real machine dimensions. Everything the rest of the project stands on is created here — the seam contracts, the `TABLE` registry, the ported time-of-impact physics core, the fixed-step loop, the Blender-to-glb export pipeline, a Babylon scene at the fixed authored view, keyboard input, a dev tuning panel, replay goldens, and CI with boundary lint. The pipeline and the feel are the deliverable, not the art — every mesh is a placeholder primitive. Two measurement spikes open the epic and can still change its shape: if the physics loop misses its frame budget the tick rate drops and the solver is re-tuned before anything is built on it. The feel ritual against the reference machine (Stern *Dungeons & Dragons* — a feel reference only, with no art, audio or rules taken from it) starts here and never stops.

## Requirements & Constraints

- **Real dimensions or a load failure.** Playfield 514.4 x 1066.8 mm, ball 26.99 mm, flipper bat 3.125 in rubbered, default pitch 6.5 deg. The collision loader asserts playfield bounds and both flipper lengths against the reference block and throws a descriptive error on mismatch, so a wrong-size table is caught at load rather than becoming a feel problem discovered months later.
- **Feel is the acceptance criterion.** Cradle, live catch, light tap, dead bounce, post pass and backhand must all be possible. Rebounds stay lively at low speed and never pingy or airball-prone at high speed — elasticity falloff is the primary control. Occasional hops come from one explicit tunable: at zero there are no hops, at the default they occur on hard hits, and the mechanism adds no randomness.
- **Determinism is enforced, not assumed.** Identical inputs produce identical outcomes at 30, 60 and 120 Hz display rates. Owed simulated time beyond 200 ms is discarded — emitting a discard event as the frame's first event — rather than freezing or fast-forwarding. Scatter is 0 on every material and the physics PRNG is never drawn, both asserted by test.
- **Nothing tunnels and nothing stalls** at any display rate; the ball never passes through geometry; every step terminates.
- **Nudge is cabinet motion, never a force on the ball.** The ball keeps its inertia while the cabinet moves under it. The tilt bob is a real pendulum that keeps swinging and decays physically, reset by no command. The slam detector is a separate tick-windowed nudge count with its own threshold, never the bob's. Both sensors are inside the replay.
- **Balls collide plausibly** — two balls never overlap or stick, momentum transfers, and separation never drops below one diameter.
- **Flipper response within one 60 Hz display frame**; the flipper loop is entirely local to the physics step with no rules round trip.
- **Provenance is a hard gate.** The `ATTRIBUTIONS.md` entry lands *before* the file, with licences verified at source rather than from package metadata: the physics port at its pinned commit is GPL-2.0-or-later per its source file headers, the render engine packages are Apache-2.0 per their LICENSE, and the placeholder `.blend` is recorded as author-made with a date. Every ported file keeps its original copyright header plus the port marker; every new file carries the GPL-3.0 header; CI checks headers per file.
- **CI runs on every push and pull request** — typecheck, boundary lint, Vitest including replay goldens recorded in Node, build, CSP grep and the size budget — and deploys only from the default branch. The size budget is set from the measured baseline plus authored headroom and fails with measured-vs-budgeted numbers in the message.
- **No network after load.** A CSP meta tag pinned in the page and greppable in CI, a static build with relative paths, no service worker.
- **The epic closes with dated documents**: the two spike results (numbers, machines, browsers, date) and the feel-test log with its first entry per item — cradling, flipper snap, rejection/rebound — each closed as a tuning change or an accepted difference, run on both the forced-WebGL2 and the default renderer path.

## Technical Decisions

- **Layering is law and is linted, not merely documented.** `sim/**` is DOM-free, engine-free, wall-clock-free and unseeded-random-free (no `window`, `document`, `performance`, `Date`, `Math.random`, timers, `localStorage`, `navigator`, `globalThis`). `presentation/**` imports only `sim/contracts` and `sim/table`. `host/**` never imports `sim/physics` or `sim/rules`. The engine's own physics plugin is banned everywhere. A device-name string literal (the `s_`, `c_`, `l_`, `f_`, `gi_`, `bd_`, `shot_`, `show_` prefixes) outside the table file and `test/**` is a lint error. dependency-cruiser enforces all of it in CI.
- **One clock behind one constant.** `TICK_HZ` lives in a single contracts file and `tick` is the only notion of time inside `sim/`. Every duration is authored in ms in the tuning file and converted to ticks once at load; any other literal millisecond or tick arithmetic inside `sim/` fails a CI check.
- **Loop contract.** `advance(elapsedMs, transitions)` owes `elapsed x TICK_HZ` steps and carries the fractional remainder. Per step: physics consumes the input frame in force at that tick plus the commands issued at the previous tick, then `rules.step` runs — every step, even with no events. The frame output carries every event and command from all N steps in tick order, with empty arrays and an unchanged snapshot when N is 0. Presentation renders the latest snapshot without interpolation.
- **Closed seam contracts,** discriminated on `type`, every event and command carrying `tick`. Contracts are generic over the name unions; the name unions are derived from `typeof TABLE` in a separate file; contracts never import the table.
- **One table registry.** A single `TABLE as const` is the sole source of switches (each with a `settleTicks` class), coils, ball devices (capacity, slot switches in fill order, eject coil, search order), reference dimensions and glb node names. It is imported directly — no table interface, loader API or plugin API. Tunables carry a unit-suffixed name, a `source` and a `confidence`; do-not-invent figures ship marked `unverified`.
- **Physics is ported, not derived.** Solver constants are verbatim and never tunable — changing one is a physics-version bump that re-records every golden. The flipper is the ported mover (strength, ramp-up, end-of-stroke torque and angle, return strength, inertia one-third m r squared); documented pulse/hold figures from elsewhere are calibration comments, never parameters. The cabinet oscillator is ported, but its ball coupling is re-derived as table-frame motion and pinned by a golden replay.
- **Hardware rules live inside the physics step,** each behind its coil and gated only by coil enable/disable — flippers and the manual plunger in this epic. A switch or button reaches its coil on the same tick.
- **Ball devices.** The machine carries 4 balls, asserted at boot. The trough parks entering balls unconditionally into the lowest empty slot and ejects the highest filled slot, one ball per pulse, at the authored pose; the shooter lane is non-parking — the served ball stays simulated resting on the plunger tip. Device counts are the number of closed slot switches and nothing else. The *opening* of the shooter-lane switch is the one thing that means "plunged" and drives the launch event and the in-play count.
- **Switch discipline.** Physics emits playfield and mechanism switches as edges only, with per-switch hysteresis and settle classes; the loop emits the button switches from input-frame transitions; rules never debounce. Switch zones test the ball's per-tick swept segment, never its end position.
- **Units and frames.** The table frame (playfield-local mm, right-handed, origin bottom-left nearest the player, X right, Y up the playfield, Z toward the glass) is canonical; physics keeps VP units internally; the glb and the scene are metres. Exactly one file exports the three conversions and no other file converts units or axes. Geometry is authored unpitched; pitch is applied by physics as the gravity vector and by presentation as a rotation of the playfield root about a pitch pivot, with the cabinet staying level.
- **Blender owns placement; the export script is the contract's enforcer.** One `.blend` is the sole owner of positions, meshes and switch zones. The export tool validates node names, uniqueness, one-material-per-mesh and every custom property against a JSON dump of the table, then writes the glb for presentation and a collision JSON (mm, table frame) for physics, exiting non-zero and naming the offending node on any violation. `sim/` never parses glb. Both loaders fail fast on a missing node or unknown property. Node prefixes: `col_` collision scaffolding that reduces to the ported primitive set, `sw_` switch zones, `vis_` visuals, `l_` inserts with lens and cup geometry, mechanisms named as their device; exactly two top-level nodes plus the pitch pivot; walls and floor have real thickness; playfield collision is one compound body.
- **Replays are first-class.** A replay is a header (the whole game-start bundle, physics seed, tick rate, table hash, asset hash, physics version) plus the ordered input transitions. The state hash is FNV-1a over canonical JSON of the game state plus ball positions quantised to 0.01 mm. Browser parity is asserted on the game-state portion only; ball positions are asserted in Node.
- **Testing shape.** Rules are tested headless through a switch-script DSL typed by the switch names; physics is tested by replaying goldens and asserting the hash; the only presentation test is a headless-engine load smoke test.
- **Greenfield, single package** on the pinned toolchain (Node 24 LTS, pnpm, Vite, TypeScript with a `tsc --noEmit` gate only and explicit `types` with no `baseUrl`, Vitest, dependency-cruiser, the render engine core and loaders, Blender, glTF 2.0). The directory seed is fixed and created in the scaffold story.
- **Error policy.** Load-time paths throw and boot reports them in the host error panel; step paths never throw — invariant violations are dev-mode assertions and device failure is an event. Only `host/` logs; no telemetry; nothing reads env at runtime.
- **Naming.** Files kebab-case, types PascalCase, events snake_case on a four-phase lifecycle, entities identified by table name and balls by id rather than index.

## UX & Interaction Patterns

- **One fixed authored camera,** no camera controls; this epic renders from it directly — the walk-up and attract show are later work.
- **Default keys:** left and right Shift for the flippers, Enter to plunge with hold-for-strength, Space and the arrow keys to nudge, 1 for Start. The key-to-action map lives only in host input and key codes never enter `sim/`; each transition is tick-stamped from the DOM event timestamp against the accumulator origin.
- **Boot is a press-to-begin gesture** before the engine is created and before any asset loads; the engine is created once, right-handed; a query parameter forces the WebGL2 floor path for the feel ritual's second pass.
- **Dev tuning panel** lists every table tunable with its value, source and confidence, hot-applies an edit to the running sim, and exports the current set back to the tuning file in that file's own format. A hot-apply during a recording invalidates the recording so it cannot be saved as a golden.

## Cross-Story Dependencies

- **The two spikes gate the epic.** Nothing else lands before them. Spike 1 sets the tick rate, and on failure the solver re-tune is logged as the next piece of work before the scaffold story. Spike 3 creates the CI workflow and the deploy, sets the size budget, and records the one-glb-versus-split decision.
- **The scaffold story (contracts, table registry, tuning, boundary lint) precedes every later story** and extends the workflow created by spike 3 into the full check set.
- **The asset-pipeline story supplies the frames module, the collision JSON and the glb** that the physics loader, the scene, and the serve-roll-drain story all depend on.
- **The loop story supplies the fixed-step conductor, the trough serve and the drain** that the flipper/plunger story and the nudge story build on.
- **The goldens story depends on the behaviours from the three stories before it**; any change to the tick rate or to a solver constant re-records every golden. The feel-ritual story depends on replay record/play and on the tuning file's provenance fields.
- **Downstream:** Epic 2 draws the real playfield geometry and replaces the placeholder behind the same node contract and the same table registry, so nothing here may hard-code placeholder-specific geometry. This epic must not pre-build modes, the lighting colour grammar, audio, persistence or the settings panel — the rules layer here is only the minimal step that runs after every physics step.
