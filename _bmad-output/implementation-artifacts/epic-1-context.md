# Epic 1 Context: First Flip — a ball and two flippers that feel right

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Epic 1 turns the repository into a playable vertical slice: the author opens a build in a browser and plunges, flips, cradles, taps, nudges and drains a ball on a bare playfield at real machine dimensions. Everything the rest of the project stands on is created here — the seam contracts, the `TABLE` registry, the ported time-of-impact physics core, the fixed-step loop, the Blender-to-glb export pipeline, a scene at the fixed authored view, keyboard input, a dev tuning panel, replay goldens, and CI with boundary lint. The pipeline and the feel are the deliverable, not the art: every mesh is a placeholder primitive. Two measurement spikes opened the epic and can still change its shape — a missed frame budget drops the tick rate and forces a solver re-tune. The feel ritual against the reference machine (a feel reference only; no art, audio or rules are taken from it) starts here and never stops.

## Requirements & Constraints

- **The CSP is pinned to exactly `default-src 'self'; connect-src 'self' blob:; img-src 'self' blob:`** — carried as an `index.html` meta tag, grepped in CI, with the build failing if the tag is absent. It is the enforcement of "local storage only, no network calls after load", and it constrains what the renderer may fetch (see WebGPU below). `blob:` is admitted because the engine serves images embedded in a `.glb` through `blob:` URLs, so a textured asset cannot boot without it; the no-network guarantee is unchanged because `blob:` is a same-document scheme that cannot reach the network, and the guarantee still rests entirely on `connect-src` admitting no remote origin. `data:` was deliberately **not** admitted and was proven unnecessary in a real browser — keep the grant minimal, and prove any future widening in a browser before pinning it. The exact string is duplicated across several enforcement points (the entry HTML, the dist checker, the spike harness page, and exact-string test pins); changing it means changing all of them together or the build fails.
- **A headless engine never decodes images, so the automated suite cannot see renderer-level breakage.** A per-story smoke in a real browser is what catches it — the CSP defect above passed 442 green tests. Do not read a green test run as proof the build renders.
- **Measure the production artifact, never the dev server.** Every performance and payload number in this epic comes from a real production build (`vite build` + `vite preview`, or the deployed static build). Treat this as standing practice, not a measured effect: the dev-vs-production delta it was originally justified by did not reproduce in a same-session A/B on identical code. The reason is that production is what ships.
- **The frame-budget outcome is `TICK_HZ = 1000`, provisional.** The bar — p95 sim cost of 4 ms or less per 60 Hz frame — gates on Chrome/Windows, Chrome/macOS and Safari/macOS; the two macOS legs are author-owned and still unmeasured, so a tick-rate change remains possible and later stories must not treat 1000 Hz as final. Edge/Windows is measured and recorded but is best-effort *for this gate only*; its number never decides the verdict. That is a frame-budget carve-out, not a support-tier demotion — Edge keeps its place in the boot message, the release matrix and the platform requirement. Safari was **not** demoted: it runs a different JavaScript engine, is still unmeasured, and is the real remaining performance risk.
- **Real dimensions or a load failure.** Playfield 514.4 x 1066.8 mm, ball 26.99 mm, flipper bat 3.125 in rubbered, default pitch 6.5 deg. The collision loader asserts playfield bounds and both flipper lengths against the reference block and throws a descriptive error on mismatch, so a wrong-size table is caught at load rather than becoming a feel problem discovered months later.
- **Feel is the acceptance criterion.** Cradle, live catch, light tap, dead bounce, post pass and backhand must all be possible. Rebounds stay lively at low speed and never pingy or airball-prone at high speed — elasticity falloff is the primary control. Occasional hops come from one explicit tunable: at zero there are none, at the default they occur on hard hits, and the mechanism adds no randomness.
- **Determinism is enforced, not assumed.** Identical inputs produce identical outcomes at 30, 60 and 120 Hz display rates. Owed simulated time beyond 200 ms is discarded — emitting a discard event as that frame's first event — rather than freezing or fast-forwarding. Scatter is 0 on every material and the physics PRNG is never drawn, both asserted by test. Nothing tunnels and nothing stalls at any display rate; every solver step terminates.
- **Nudge is cabinet motion, never a force on the ball.** The ball keeps its inertia while the cabinet moves under it. The tilt bob is a real pendulum that keeps swinging and decays physically, reset by no command. The slam detector is a separate tick-windowed nudge count with its own threshold, never the bob's. Both sensors are inside the replay.
- **Balls collide plausibly** — two never overlap or stick, momentum transfers, separation never drops below one diameter. **Flipper response lands within one 60 Hz display frame**, the loop entirely local to the physics step.
- **Provenance is a hard gate.** The attribution entry lands *before* the file, with licences verified at source rather than from package metadata. Ported files keep their original copyright header plus the port marker; every new file carries the project licence header; CI checks headers per file.
- **CI runs on every push and pull request** — typecheck, boundary lint, Vitest including replay goldens recorded in Node, build, the CSP grep and the size budget. The size budget is set from the measured production baseline plus authored headroom and fails with the measured and budgeted numbers in the message.
- **Deploying is a `main`-only rule with one temporary, self-cancelling exception.** The deploy workflow is triggered on the epic branch `DW-1-epic1` plus `workflow_dispatch` purely so the spike could measure a live deployment before Epic 1 merges. Removing that epic-branch trigger and narrowing the workflow back to `main` plus `workflow_dispatch` is itself an acceptance criterion that must be satisfied before Epic 1's merge gate, restoring the `main`-only shipping rule. The spike record also states that the measured artifact was built from an unmerged branch and stays provisional until it reruns from `main`.
- **The epic closes with dated documents:** both spike results (numbers, machines, browsers, date, and which legs gate) and the feel-test log with its first entry per item — cradling, flipper snap, rejection/rebound — each closed as a tuning change or an accepted difference, run on both the forced-WebGL2 and the default renderer path.

## Technical Decisions

- **Layering is law and is linted, not merely documented.** `sim/**` is DOM-free, engine-free, wall-clock-free and unseeded-random-free. `presentation/**` imports only `sim/contracts` and `sim/table`. `host/**` never imports `sim/physics` or `sim/rules`. The engine's own physics plugin is banned everywhere. A device-name string literal outside the table file and `test/**` is a lint error. Dependency-cruiser enforces all of it in CI.
- **One clock behind one constant.** `TICK_HZ` lives in a single contracts file and `tick` is the only notion of time inside `sim/`. Durations are authored in ms in the tuning file and converted to ticks once at load; any other literal millisecond or tick arithmetic inside `sim/` fails a CI check. Changing the tick rate or any solver constant is a physics-version bump that re-records every golden.
- **Renderer selection happens once at boot, under the pinned CSP.** The engine is created once via the async engine factory, right-handed, after the press-to-begin gesture. WebGL2 is the floor and always renders. WebGPU is taken only where it can actually initialise under the pinned CSP — its transpiler must be served from our own origin, never a CDN — and otherwise falls back to WebGL2 **silently**. `?renderer=webgl2` forces WebGL2 in every case, and no feature may require WebGPU. A known open defect has the WebGPU path failing on the first alpha-blended material and falling back silently; it is routed to the later browser-matrix story, so WebGL2 is in practice the rendering path for this epic — the dual-path feel ritual still runs both.
- **Loop contract.** `advance(elapsedMs, transitions)` owes `elapsed x TICK_HZ` steps and carries the fractional remainder. Per step: physics consumes the input frame in force at that tick plus the commands issued at the previous tick, then the rules step runs — every step, even with no events. The frame output carries every event and command from all N steps in tick order, with empty arrays and an unchanged snapshot when N is 0. Presentation renders the latest snapshot without interpolation.
- **Closed seam contracts,** discriminated on `type`, every event and command carrying `tick`. Contracts are generic over the name unions; the name unions derive from the table type in a separate file; contracts never import the table.
- **One table registry.** A single frozen `TABLE` is the sole source of switches (each with a settle-ticks class), coils, ball devices (capacity, slot switches in fill order, eject coil, search order), reference dimensions and glb node names. It is imported directly — no table interface, loader API or plugin API. Tunables carry a unit-suffixed name, a source and a confidence; do-not-invent figures ship marked unverified.
- **Physics is ported, not derived.** Solver constants are verbatim and never tunable. The flipper is the ported mover (strength, ramp-up, end-of-stroke torque and angle, return strength, inertia one-third m r squared); documented pulse/hold figures from elsewhere are calibration comments, never parameters. The cabinet oscillator is ported, but its ball coupling is re-derived as table-frame motion and pinned by a golden replay.
- **Hardware rules live inside the physics step,** each behind its coil and gated only by coil enable/disable — flippers and the manual plunger in this epic. A switch or button reaches its coil on the same tick, with no rules round trip.
- **Ball devices.** Four balls, asserted at boot. The trough parks entering balls unconditionally into the lowest empty slot and ejects the highest filled slot, one per pulse, at the authored pose; the shooter lane is non-parking, the served ball resting simulated on the plunger tip. Device counts are the number of closed slot switches and nothing else. The *opening* of the shooter-lane switch is the one thing that means "plunged" and drives the launch event and the in-play count.
- **Switch discipline.** Physics emits playfield and mechanism switches as edges only, with per-switch hysteresis and settle classes; the loop emits the button switches from input-frame transitions; rules never debounce. Switch zones test the ball's per-tick swept segment, never its end position.
- **Units and frames.** The table frame (playfield-local mm, right-handed, origin bottom-left nearest the player, X right, Y up the playfield, Z toward the glass) is canonical; physics keeps its ported internal units. Exactly one file exports the three conversions and no other file converts units or axes. Geometry is authored unpitched; pitch is applied by physics as the gravity vector and by presentation as a rotation of the playfield root about a pitch pivot, with the cabinet staying level.
- **Blender owns placement; the export script is the contract's enforcer.** One source file owns every position, mesh and switch zone. The export tool validates node names, uniqueness, one-material-per-mesh and every custom property against a dump of the table, then writes the glb for presentation and a collision file (mm, table frame) for physics, exiting non-zero and naming the offending node on any violation. `sim/` never parses glb; both loaders fail fast on a missing node or unknown property. Node prefixes cover collision scaffolding that reduces to the ported primitive set, switch zones, visuals, inserts with lens and cup geometry, and mechanisms named as their device; exactly two top-level nodes plus the pitch pivot; walls and floor have real thickness; playfield collision is one compound body; static meshes carry a second UV set and a light-group property.
- **Replays are first-class.** A replay is a header (the whole game-start bundle, physics seed, tick rate, table hash, asset hash, physics version) plus the ordered input transitions. The state hash is FNV-1a over canonical JSON of the game state plus ball positions quantised to 0.01 mm. Browser parity is asserted on the game-state portion only; ball positions are asserted in Node.
- **Testing shape.** Rules are tested headless through a switch-script DSL typed by the switch names; physics is tested by replaying goldens and asserting the hash; the only presentation test is a headless-engine load smoke test — which, being headless, proves the scene graph loads and nothing about what the browser actually draws.
- **Error policy.** Load-time paths throw and boot reports them in the host error panel; step paths never throw — invariant violations are dev-mode assertions and device failure is an event. Only `host/` logs; no telemetry; nothing reads env at runtime.
- **Naming.** Files kebab-case, types PascalCase, events snake_case on a four-phase lifecycle, entities identified by table name and balls by id rather than index.

## UX & Interaction Patterns

- **One fixed authored camera,** no camera controls; this epic renders from it directly — the walk-up and attract show are later work.
- **Default keys:** left and right Shift for the flippers, Enter to plunge with hold-for-strength, Space and the arrow keys to nudge, 1 for Start. The key-to-action map lives only in host input and key codes never enter `sim/`; each transition is tick-stamped from the DOM event timestamp against the accumulator origin.
- **Boot is a press-to-begin gesture** before the engine is created and before any asset loads. The renderer choice behind it is invisible to the player — a WebGPU attempt that cannot initialise or cannot render degrades to WebGL2 with nothing surfaced — and the forced-WebGL2 query parameter exists for the feel ritual's second pass.
- **Dev tuning panel** lists every table tunable with its value, source and confidence, hot-applies an edit to the running sim, and exports the current set back to the tuning file in that file's own format. A hot-apply during a recording invalidates the recording so it cannot be saved as a golden.

## Cross-Story Dependencies

- **The two spikes gated the epic and are closed.** The tick rate is set to 1000 Hz and marked **provisional** — the two macOS gating legs are author-owned and still unmeasured, so later stories should treat a tick-rate change as still possible. The CI workflow, the deploy, the pinned CSP and the size budget all exist and are extended from here rather than created.
- **Story 1.2 leaves one debt that Epic 1 must clear before merging:** the epic-branch deploy trigger it added has to be narrowed back to `main` plus `workflow_dispatch`. Whichever story or gate closes the epic must confirm it, and no later story may rely on the epic branch deploying.
- **The scaffold (contracts, table registry, tuning, boundary lint) exists** and precedes every later story; it owns the tick-rate constant's home and the single load-time ms-to-ticks conversion, and it extended the workflow into the full check set. Build on those contracts rather than widening them.
- **The asset pipeline exists:** the frames module, the collision file and the glb are in place, and the physics loader, the scene and the serve-roll-drain story consume them. The placeholder renders at real dimensions, pitched, from the fixed camera, on WebGL2.
- **The loop story supplies the fixed-step conductor, the trough serve and the drain** that the flipper/plunger story and the nudge story build on.
- **The goldens story depends on the behaviours from the three stories before it**; any change to the tick rate or to a solver constant re-records every golden. The feel-ritual story depends on replay record/play and on the tuning file's provenance fields.
- **Downstream:** Epic 2 draws the real playfield geometry and replaces the placeholder behind the same node contract and the same table registry, so nothing here may hard-code placeholder-specific geometry. Epic 6 re-asserts the same pinned CSP and the `main`-only deploy rule, so leaving either loosened here breaks a later gate; the open WebGPU defect is routed to its browser-matrix story. This epic must not pre-build modes, the lighting colour grammar, audio, persistence or the settings panel — the rules layer here is only the minimal step that runs after every physics step.
