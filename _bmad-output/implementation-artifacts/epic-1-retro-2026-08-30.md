## Findings

### Finding 1 — HIGH — A fresh checkout of this repository fails 43 tests, including the licence-header gate

**Source:** `pnpm test` on the merged feature branch `fefc63e`:
`Test Files 2 failed | 74 passed (76)`, `Tests 43 failed | 907 passed | 21 skipped (971)`.
Against CI on the epic tip `8a2b6d1` (run `33307714415`): **green**, 949 passed | 22 skipped.

**Cause — proven, not inferred.** `core.autocrlf=true` on the author's machine. `.gitattributes`
pins `eol=lf` for `_bmad-output/implementation-artifacts/*.{md,yaml}`, `_bmad/custom/*.yaml`,
`*.sh`, and `test/replays/**` — and every one of those paths is verified LF on disk. Nothing pins
`src/**`, `test/*.ts`, or `.github/workflows/*`, and every one of those is verified **CRLF** on disk.
The failing assertions are the signature: `expected '// Ported from vpdb/vpx-js (GPL-2.0-o…' to be
'// Ported from vpdb/vpx-js (GPL-2.0-o…'` — two strings that render identically and differ by a
trailing `\r`; and `expected '' to match /\bpush:\s*\n(?!\s*branches:)/`, where a CRLF-blind
extraction regex returned empty.

**Why ten stories never saw it.** Every agent *wrote* source files, and a written file keeps its LF
bytes in the working tree; `autocrlf` converts on **checkout**, and no story ever checked the tree
out. The epic worktree was created before most of these files existed and then only ever written to.
The merge into the main checkout is the **first real checkout of this code**, and it is the first
time the tests met the bytes a new contributor would get.

**Why it is HIGH rather than cosmetic.** The 43 failures include `test/sim-boundary.test.ts`'s
AD-16 header-provenance suite — the gate that enforces the port markers on every vpx-js and vpinball
file. `CLAUDE.md` makes provenance a hard, non-negotiable requirement. **A fresh clone on Windows
cannot verify its own licence headers**, and the failure looks like a licensing defect rather than a
line-ending one, which is precisely how a real provenance regression would be dismissed as noise.

**Disposition:** fix now. Extend `.gitattributes` to pin source and test files (`* text=auto eol=lf`,
or explicit `src/** test/** .github/**` entries consistent with the existing style), then verify with
a fresh clone or `git checkout -- .` after re-normalisation.

### Finding 3 — CONFIRMED SOUND — DW-70's deliberate red is live, contained, and non-vacuous

**Source:** on the merged branch, `pnpm check:ad7` exits 1, while
`pnpm exec vitest run test/ad7-device-slots.test.ts` **passes** (1/1), asserting that the harness
process exits non-zero *and* that its failure content names `DW-70`, `AD-7` and `bd_trough` —
the reason, not merely the exit code.

This is the rare case of a knowingly-shipped architecture violation done properly: the violation is
real (`src/sim/loop/index.ts` copies the physics machine's `deviceSlots` onto `GameState` after
`rules.step()` returns, against AD-7), the red is running rather than documented, and the containment
asserts the failure's *content* so it cannot silently become a different failure. The runner further
proved non-vacuity by applying a partial rules-layer fix, observing `check:ad7` go green **and** the
wrapper go red, then reverting byte-identically.

**Disposition:** no action. Routed to Story 2.5 at the decision sheet; the red stays red until then.

### Finding 4 — PROCESS — The vacuity pattern is real, and Rule 19 measurably changed it

**Source:** `cycle-log-epic-1.md` — 10 occurrences of `vacuous`, 11 of `vacuity`, 3 of
`could_not_fail`, 2 `adr_verifications_complete … result=unverified`, 1 `result=fail`, 12 `result=pass`.

Four vacuous assertions **shipped** in the epic's first stretch, including the ADR gate's own
`pass_commands_empty` recorded against a value typed `readonly never[]` — an assertion that could not
fail, emitted by the layer the whole pipeline trusts most. After Rule 19 landed, three more were
caught **before** shipping: an obvious fixture that proved nothing against the real `tuning.ts`; a
spec claim that "a mutation reddens both consumer suites" which reddened one when actually applied;
and a golden's "real contact" assertion satisfied with no flipper input at all.

The two `result=unverified` entries are the rule working as designed — a pass with no demonstrated
mutation is recorded as unverified rather than as evidence.

**Disposition:** accept — the rule is doing its job. The lesson to carry: the gates most worth
falsifying are the ones nobody reviews, and in this pipeline that is the lead's own ADR gate.

### Finding 6 — PROCESS — Every claim in this epic was validated in exactly one environment

The thread joining Findings 1 and DW-107. Two failures, mirror images of each other:

- **DW-107:** `export-py-skip-visibility.test.ts` was red on CI for ~16 hours across two full story
  pipelines, because every gate runs `pnpm test` locally and **no gate reads CI**. Local green was
  never the same claim as CI green.
- **Finding 1:** 43 tests are red in a fresh checkout while CI is green, because CI's Linux checkout
  is LF and a Windows checkout is CRLF.

One epic produced both directions of the same root cause: a single environment treated as
authoritative for a cross-platform claim. Notably, DW-107 **could not be reproduced locally at all** —
`FORCE_COLOR`, `CI` and `GITHUB_ACTIONS` all fail to make the nested vitest run colourise on Windows,
because that decision is platform-gated. Filed as BUG 3 of bug report #4.

## Acceptance verdict

### **accepted-with-open-items**

Criteria were **declared**, not profiled: Epic 1's goal paragraph names the vertical slice it must
produce, plus FR-4..FR-13, NFR-2..NFR-9 and AR-1..AR-35 coverage.

**Met.** Every element of the declared as-built checklist exists and is exercised: seam contracts and
the `TABLE` registry, the vpx-js port, the fixed-step loop, a placeholder `.blend` through
`export.py`, a Babylon scene at the fixed view, keyboard input, the dev tuning panel, replay goldens
with cross-engine state hashes, and CI with boundary lint. All 10 stories are `done`,
`pending_stories` is empty, CI was green on the epic tip, and all four static gates pass on the
merged result. The ledger closes at `open=0` with no story key and no `burndown` owner holding work.

**Open items.** Finding 1 — a fresh checkout fails 43 tests including the provenance gate — is a real
defect in the shipped state, but it is a checkout-configuration defect rather than a code defect: the
committed bytes are correct and CI proves the code works. It is a one-line-class fix and does not
undermine any story's acceptance. DW-70 ships as a knowingly-accepted, well-contained architecture
violation with a deliberate red, routed to Story 2.5 by author decision.

Not `accepted` outright, because a repository whose licence-header gate fails on a fresh clone should
not be recorded as clean. Not `rejected`, because nothing the epic promised is missing or broken.
